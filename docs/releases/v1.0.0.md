# WhatsApp Readonly Bridge v1.0.0 - signed inbound webhooks and durable JSONL

This release relaunches the project as a focused inbound WhatsApp Cloud API webhook receiver with signed POST validation, defensive payload parsing, durable JSONL append, retry deduplication, hardened deployment examples, and tested downstream readers.

## Highlights

- Requires `WA_VERIFY_TOKEN` and `WA_APP_SECRET`; placeholder values fail startup.
- Validates `X-Hub-Signature-256` before JSON parsing.
- Stores stable nine-key JSONL records.
- Suppresses duplicate Meta retry deliveries in the normal single-process deployment.
- Provides Docker, Compose, systemd, reader, stats, Telegram digest, Discord digest, local API, and smoke-test examples.
- Publishes container tags `latest`, `1`, `1.0`, and `1.0.0`.

## Installation

See `README.md` for Docker, direct Python, and systemd setup. The published image is:

```bash
docker pull ghcr.io/marketingboer/whatsapp-readonly-bridge:latest
```

## Upgrade impact

- `WA_APP_SECRET` is now required.
- Unsigned or malformed POST requests return `401`.
- Direct execution binds to loopback by default.
- Compose stores data in a named `/data` volume.
- JSONL records use the stable nine-key schema.

## Known limitations

The bridge does not send or reply through WhatsApp, does not download media bytes, and does not provide a browser UI, shared inbox, campaign tool, chatbot framework, database queue, or multi-replica delivery guarantee.
